# Support

This is the organization-wide default support policy.

## Where to ask

Use the issue tracker of the repository that actually owns the problem.

Before filing an issue:

- check the repository README and existing issues;
- include the exact branch/version/commit when relevant;
- include concise reproduction steps and relevant logs;
- remove tokens, private identifiers, and unrelated log noise.

## Upstream forks

For repositories maintained primarily as upstream/reference forks, general product support belongs with the upstream project unless the issue is caused by a ZhanfgBuild-specific patch, build, configuration, or integration.

## Experimental work

Prototype and research repositories may not provide stable compatibility or long-term support. A successful build is not automatically proof of runtime or device compatibility.
